Executive summary

One workspace for the whole engagement

Most testers juggle a scope document, scanner output, a notes app, a screenshots folder and a report template. OffsecHub keeps all of it in one place, in the order an engagement actually runs.

  1. Scope

    Include and exclude rules for IPs, CIDRs, hostnames, wildcards and URLs, plus a checker for "can I touch this?"

  2. Targets

    Every host, service and URL with its live scope status.

  3. Recon

    Import Nmap XML, nuclei JSONL and host lists, from the app or your terminal. Excluded hosts never get in.

  4. Testing

    OWASP WSTG, API Top 10, external, internal/AD and AWS checklists, and an operator log for SOC deconfliction.

  5. Evidence

    Screenshots, requests and dumps, encrypted as they stream in, fingerprinted with SHA-256 and linked to findings.

  6. Findings

    CVSS 3.1 calculator, CWE, a triage workflow and a library of reusable write-ups.

  7. Report

    Readiness checks, then HTML (print to PDF), Markdown or JSON with an evidence appendix.

Findings

Why keep engagements in a local vault

Pentest data is a map of how to break into a client. These are the problems OffsecHub was built to fix, written up the way you would write them for a client.

RefFindingSeverityFix in OffsecHub
OH-01

Every client's attack map sits on one shared server

Collaboration platforms need a server that someone runs, patches and trusts. One compromise exposes every client at once.

Critical
Fixed

Each engagement lives in an encrypted vault folder you control. There is no server to breach and no account to phish.

OH-02

Evidence scattered across Downloads, chat and screenshot folders

Files go missing, get overwritten, or stay unencrypted on a laptop long after the engagement.

High
Fixed

Evidence streams straight into the vault under its own key, gets a SHA-256 fingerprint and links to its finding.

OH-03

Testing a host that was never in scope

A wildcard that matches too much or a scanner range typed from memory, and you're outside your authorisation.

High
Fixed

Scope rules are checked on every import and shown on every target. Excluded hosts are never imported.

OH-04

Plaintext copies left behind

Temp files, upload spools, access logs and crash dumps quietly keep what you meant to protect.

Medium
Fixed

The database lives in memory, uploads are encrypted as they stream, and there are no access logs or core dumps. Locking drops the key.

OH-05

Report day takes the whole day

Copying findings between documents, re-scoring CVSS and hunting for the right screenshot.

Medium
Fixed

A finding library, a CVSS calculator and readiness checks, then one click to HTML, PDF, Markdown or JSON.

OH-06

No internet inside the client network

Cloud tools stop working on an isolated test VLAN, a Kali VM without egress, or a plane.

Info
Fixed

Everything works offline. No sign-in, no telemetry, no update checks.

Methodology

From install to report in six steps

Each step shows the real app. Under every screenshot is its SHA-256, computed in your browser, the way OffsecHub fingerprints evidence.

  1. Install and open OffsecHub

    Run the installer for your system. There is no account to create and no sign-up.

  2. Create a vault and save the recovery key

    Pick a folder and a password. Store the recovery key somewhere safe: it is the only way back in if you forget the password.

  3. Start an engagement and set the scope

    Add the client, the testing window and the rules of engagement, then the include and exclude rules.

  4. Import your recon

    Drop in Nmap, nuclei or a host list, or push results from a terminal while the app is open:

    $ offsechub import ACME-EXT-26 scan.xml --tool nmap

  5. Test and collect evidence

    Work through a checklist, log what you run, and attach screenshots and requests to findings as you go.

  6. Write the report

    Fix what the readiness check flags, then export HTML (print it to PDF), Markdown or JSON.

Appendix

How the vault protects your data

Encrypted at rest

Your password goes through Argon2id (64 MiB) to unlock a random master key. The database and every evidence file are AES-256-GCM, each under its own key.

Tamper evident

Every byte is authenticated. Deleted or rolled-back key slots and a vault restored from an old copy are detected and reported.

Locked down locally

The app's local API takes a one-time launch token and checks Host and Origin on every request, so web pages and other users on the machine can't reach it.

No lock-in

The vault format is published, with test vectors, and an independent decoder opens your vault without OffsecHub.

Out of scope

OffsecHub can't protect you from malware running as you while the vault is unlocked, and folder names, file sizes and timestamps stay visible. The threat model lists every such limit.
